# 第二阶段：YOLOv8 预训练基线

这一阶段建立可运行的图片检测工具，尚未微调模型，也没有接入 SAM 2、大模型或交互页面。原 COCO 权重支持杯子、瓶子和书，另五类仍为尚未训练。

## 运行方法

在项目根目录用 PowerShell 加载原 ai-cuda，然后将图片路径替换为自己的照片：

```powershell
. .\environment\activate-ai-cuda.ps1
python -m deskvision --image 'D:\你的图片\桌面照片.jpg'
```

本工具读取 .local/config.json 的 yolo_weights，只使用已有 .pt 文件，不自动下载。也可以指定权重、计算设备和分数阈值：

```powershell
python -m deskvision --image 'D:\你的图片\桌面照片.jpg' --device cuda:0 --conf 0.25 --iou 0.7 --imgsz 640
python -m deskvision --image 'D:\你的图片\桌面照片.jpg' --device cpu
python -m deskvision --help
```

图片路径相对于当前终端，默认输出根目录相对于项目。每次输出到 runs/baseline 下独立的时间戳目录，不覆盖原图或旧记录。--output 可更换输出根目录；--font 可指定支持中文的字体。

## 输出与含义

每次成功运行保存 annotated.png 和 result.json。标注图左侧保持原图大小，右侧附八类清单，JSON 检测框仍以原图左上角为原点，不包含右侧面板。

| 字段 | 含义 |
|---|---|
| detections | 有效检测实例，包括项目编号、源编号、中文类别、分数和 xyxy 原图坐标 |
| summary | 各类支持状态与计数；尚未训练为 null，不能拿来算零误差 |
| total_supported_detections | 仅统计预训练支持类别的检出数，不代表桌面所有物品总数 |
| model、parameters | 权重名称和哈希、设备、输入尺寸、分数阈值与重复框抑制设置 |
| input、category_config | 原图及类别配置指纹，用于核对训练前后的比较条件 |
| timings_ms、versions | 本次耗时和依赖版本；首张包含初始化与预热，不能当稳定帧率 |

summary 中 supported 且 count=0 的意思是模型支持这一类，但在当前图片和参数下没有检出；不证明图中绝对没有该物品。not_trained 且 count=null 表示本阶段尚未训练或支持这一类。文件读取或模型执行失败则返回非零退出码，不保存伪造的成功空清单。

## 核心知识

OpenCV 把图片读成像素数组，YOLO 在内部缩放后检测，再把框还原为原图像素坐标。我们保留小数坐标，便于第五阶段把框交给 SAM 2。

分数阈值决定哪些预测保留。它不是识别正确率的保证，例如分数 0.84 不等于本项目验证过 84% 准确率。提高阈值可能减少误报，同时增加漏检。

IoU 表示两个框交集面积占并集的比例。重复框抑制保留分数较高的预测，抑制高度重叠候选。八类按互斥类别处理，本阶段启用跨类别抑制，避免同一罐子同时算杯子和瓶子；严重遮挡的不同实物也可能被误抑制，后续需用实际桌面数据检验。

## 已验证范围与问题

2026-10-23 使用本机已有 COCO128 图片 000000000127.jpg、000000000142.jpg 及生成的纯白图片验证。公开图片只用于流程检查，预训练可能见过这些图片，不作为未见测试或精度结论。模型和逐次结果见 reports/baseline，完整本地图片产物留在 runs/baseline，不上传未核对许可的图片。

- 000000000127.jpg：检出杯子 1、书 1。书的分数约 0.287，接近默认阈值；这说明阈值选择会影响计数。
- 000000000142.jpg：初版默认同类抑制时，一个罐子同时被识别为瓶子和杯子，预测为瓶子 2、杯子 1。启用跨类别抑制后为瓶子 2、杯子 0。牛奶盒仍被误认为瓶子，不能说这一样例已经识别正确。
- 纯白图：GPU 和 CPU 路径均可返回正常空检测，前三类为 0，后五类仍为 null。纯白图不能替代真实杂乱桌面负样本。

只做了功能与边界检查，没有完整测试集、mAP 或计数准确率；无训练、无新模型下载。最初的同类抑制和修正后的跨类别抑制记录分别保留，不覆盖旧结果。
