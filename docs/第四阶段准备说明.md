## 操作顺序

在项目 PowerShell 中激活现有环境：

```powershell
. .\environment\activate-ai-cuda.ps1
python -m deskvision.train --environment-only
```

这条命令只检查配置、解释器、本地权重、GPU 与依赖版本；通过也不表示数据已通过。普通 `python -m deskvision.train` 另外验收数据并打印计划，始终不训练。准备阶段的拒绝历史见 `reports/stage4-gate-checks.json`；用户批准试跑后，当前包已通过检查。

数据获准相应训练范围、重新导出并通过检查后，运行：

```powershell
.\environment\start-training.ps1
```

脚本打开独立可见 PowerShell，再激活 ai-cuda 并执行 `python -m deskvision.train --run`。新窗口在条件未通过时停止并保留错误；通过后显示每轮 Epoch、GPU 进度、loss 和验证指标。直接在普通工具进程里调用训练入口会被可见终端标志检查拒绝。

每轮结束在 `runs/train-metadata/` 保存配置、数据清单和权重摘要、GPU／库版本、训练损失与验证指标。完成后记录权重路径；异常或 Ctrl+C 会标明 failed／interrupted。训练产物留在 `runs/train/`，不提交大权重和图片。

## 三轮试跑的验收与后续

三轮只检查八类数据加载、GPU 反向传播、验证、日志和权重保存能否完成，不作精度承诺。loss 是模型对训练题目的误差；精确率反映检出的目标中有多少正确，召回率反映应找到的目标中找到了多少，mAP 综合不同阈值下的检测表现。极小验证集的指标会波动，不能当成最终成绩。

完成后检查训练／验证标签图、类别名称、损失是否有限、权重是否可读取，以及小五金漏检与杯瓶混淆。若显存不足，记录实际失败再修改配置并复查，不静默改用 CPU。正式训练轮数和参数依据数据规模及验证结果决定，当前入口固定首轮参数，修改需同步更新校验和说明。

独立测试集保留到模型与阈值确定后再用；本轮已有训练曲线和微调权重，没有测试集指标。
