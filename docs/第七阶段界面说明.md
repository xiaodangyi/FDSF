# 第七阶段：双路线识别界面

2026-10-24（Asia/Shanghai）。使用已安装的 Gradio 5.49.1，统一操作和展示 YOLOv8 → SAM 2 与 DeepSeek 原图识别。没有重新训练、安装依赖或使用独立测试集。

## 启动和使用

```powershell
. .\environment\activate-ai-cuda.ps1
python -m deskvision.ui
```

打开 http://127.0.0.1:7860；端口被占用时用 `--port 7861`。服务只监听 127.0.0.1，关闭公开分享。退出时在启动终端按 Ctrl+C。

1. 上传 JPG、PNG、WebP 或单帧 GIF 原图，最大 32 MiB，宽高不超过 8192。文件上传控件保留原始字节，预览与识别输入分开。
2. 默认使用第 4 阶段八类最佳权重、置信度 0.25、640 输入尺寸、自动选择设备，开启 SAM 2。高级设置可选择 COCO 基线、已有权重路径、NMS IoU、输入尺寸和设备。
3. 点击本地识别、DeepSeek 或“运行两路并比较”。DeepSeek 按钮会将原图发送至官方服务并产生 API 用量；不自动重试。密钥仍从忽略的 `.local/deepseek.env` 读取，界面不收集密钥。
4. 查看本地检测框与实例掩膜、八类数量、DeepSeek 逐件位置与存疑说明、各自 JSON、耗时和错误；下载当前结果 ZIP。

默认最佳权重路径为 `runs/train/desk8-full-20261023-204546/weights/best.pt`。若其他机器没有该文件，应在高级设置中填写自己的八类权重。COCO 基线留空使用本机配置；五个未训练类别显示“尚未训练”，对比使用破折号，不能当作零。

## 独立性与状态

两路各自读取同一上传文件。一键运行时使用两个工作线程并行处理本地推理与远程请求；DeepSeek 请求不含 YOLO 框、SAM 掩膜、另一条路线的数量或人工标签，结果也不回写训练。SAM 2 只描绘 YOLO 已有框内的轮廓，不修复类别和漏检。

只有两路都成功且原图 SHA256 相同，才计算 `DeepSeek - YOLO` 的八类数量差异。一条失败仍展示另一条结果，失败不伪造成零计数；SAM 失败时保留已生成的检测报告与图片。

更换或清空原图立即清除两路结果、对比和下载；修改本地参数只清除本地结果与对比，保留已完成的 DeepSeek 结果。会话输入修订号阻止旧任务完成后覆盖新页面，也拒绝使用已过期的排队参数。已发出的 API 请求不会因改图而取消，仍可能计费；如需保留结果，应等当前任务完成后再改输入。

所有推理事件共用长度上限 16 的串行队列，另用锁保护本地 GPU 推理，避免多个会话同时争用 GPU。一键双路内部仍可并行。服务按本机单人使用设计，不提供多用户权限管理。

## 结果与耗时

- `runs/ui/yolo/<时间-编号>/`：检测报告、检测图、可选分割图和逐实例掩膜。
- `runs/ui/deepseek/<时间-编号>/`：独立报告、脱敏请求摘要及结构化响应。
- `runs/ui/exports/<时间-编号>/双路识别结果.zip`：当前两路文件与 `数量对比.md`；单路成功或失败报告也可导出。

导出仅打包对应 UI 运行目录内的文件，拒绝指向目录外的路径和符号链接。`.local` 被下载路由显式阻止；原始运行产物和 ZIP 不入 Git。

耗时分别记录模型推理、API 请求和总处理时间。总处理时间含本次模型加载、校验和产物保存，不含队列等待、文件上传、下载及 ZIP 打包；冷启动不能作为稳定 FPS。当前每次本地识别重新加载模型，优先保证路径与设备选择正确，尚未做常驻模型缓存或视频流优化。

## 本轮验证与限制

52 项自动检查通过，覆盖独立原图传递、失败保留、空值计数、异图拒绝比较、导出边界、旧任务丢弃和 Gradio 构建，环境准备检查通过。Windows 下 Gradio 构建测试出现事件循环未关闭的 ResourceWarning，测试退出码仍为 0；没有把警告描述为项目功能失败。

同图联调只验证界面和接口，不证明真实桌面泛化、分割精度或大模型总体优于本地模型。第八阶段再固定测试组、比较计数误差、耗时与成本、整理展示和验收材料；本阶段未开始这些实验。可追溯摘要见 [检查记录](../reports/stage7-ui-checks.json)。
