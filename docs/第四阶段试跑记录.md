## 结果与限制

训练分类损失从 4.12743 降至 3.66767，训练框损失从 1.00788 到 0.89828；验证框损失从 0.48823 上升至 0.51949。链路可用，但三轮不足以判断收敛或过拟合。

训练内置最终验证：mAP50 **0.19017**、mAP50-95 **0.15884**。重新加载保存的最佳权重，按固定 FP32、batch 4、640、置信下限 0.001、NMS IoU 0.7 协议独立验证：mAP50 **0.17777**、mAP50-95 **0.14244**，宏平均精确率 **0.00633**、召回率 **0.67188**。两种验证批处理设置不同，数值不完全一致；独立验证作为下表及 JSON 报告的固定协议，不与内置结果混成一个数字。

| 类别 | 验证图片／实例 | AP50 | AP50-95 |
|---|---:|---:|---:|
| 杯子 | 3／4 | 0.0984 | 0.0642 |
| 瓶子 | 3／3 | 0.9125 | 0.7633 |

瓶子仅有三个验证实例，即使 AP50 较高也不代表泛化可靠。螺母和垫圈 AP 为零，其他新增类别仍弱。验证精确率和召回率不是 0.25 推理阈值的成绩：指标从低分预测计算曲线，不能把较高召回率解释为实际清点可用。

实际用 `best.pt` 对两个验证样例做默认阈值 0.25 推理：`loco_val_000` 真值为螺丝、螺母、垫圈各 2，模型全漏检；`oi_38451ec391f20ab5` 真值为杯子、瓶子各 1，也全漏检。中文可视化与 JSON 已保存，没有为了好看降低阈值。当前模型**不能用于可靠八类清点**。

完整指标、权重摘要、配置和逐轮损失见 `reports/desk8-pilot-20261023-192025-validation.json`；两个样例结果索引和错误模式拒绝检查见 `reports/stage4-inference-checks.json`。训练曲线与标签叠加图已实际查看。没有使用独立测试组，也没有宣称超过原 COCO 基线；新旧类别体系不同，公开样本亦可能存在预训练重叠。

## 推理和复核命令

```powershell
. .\environment\activate-ai-cuda.ps1
python -m deskvision --mode finetuned --weights 'runs/train/desk8-pilot-20261023-192025/weights/best.pt' --image 'data/desk8-train-v1/images/val/loco_val_000.png' --device cuda:0
python -m deskvision.evaluate --run-name desk8-pilot-20261023-192025
```

默认 `--mode baseline` 保留 COCO 三类基线；`finetuned` 必须显式选择八类权重，精确核对类别名称和编号。八类此时显示“已微调，待验收”，零检出表示这次调用没有检测结果，不是图中没有目标。

## 修正与后续

- 训练库在标签目录生成 `train.cache`、`val.cache`，核验只允许 labels 根目录下已知三个划分缓存；未知额外文件仍拒绝。
- 最佳权重最终验证会再次触发轮结束回调，现已单独记录，避免产生假的第四轮；本轮元数据作了有说明的修正，原始 CSV 和终端记录不改写，没有为此重训。
- 后续可见窗口指定 UTF-8 输出，减少 PowerShell 转录中的中文编码问题；本次指标以有效 UTF-8 JSON 和 CSV 为依据。
- 20 项测试通过，保存权重重载及两个中文输出可用；这只验收代码链路。

下一步优先补足书、橡皮及真实桌面五金场景、独立验证会话和确认的负样本，再制定更长的训练计划。三轮试跑不是最终模型，本轮不擅自扩成几十轮，也不开始第五阶段。
