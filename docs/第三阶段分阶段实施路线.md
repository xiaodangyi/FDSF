## S0：需求与代码基线

**通俗解释：**先整理题目和已有工具，避免写完漏交。

1. 渲染 PDF 全页，核对学习内容、完整项目、验收要求，记录哈希和链接。
2. 区分原文、用户补充、实施选择，列明差距和交付标准。
3. 将现有模型、界面、测试、依赖与历史证据迁入 FDSF，记录来源提交与未提交文件。
4. 在 FDSF 中执行已有离线检查，保留退出码、条数、警告和原始日志。
5. 核对文件清单、文档链接、密钥排除，提交并推送。

**交付/验收：**本路线、需求说明、清单、源码、报告与真实提交；旧实验不能说成本轮重跑。

## S1：核验 Ubuntu 与识别资源

**通俗解释：**先通电试机，确认 Linux 真能跑模型。

1. 查询 Ubuntu、Python、CPU/内存、磁盘、GPU与驱动；用户报告版本先核验。
2. 核对八类 `best.pt`、SAM 2.1 tiny、类别、演示图片的来源/哈希/权限；私下配置 DeepSeek key。
3. 准备 Python 3.12、Linux 依赖、中文字体，不照搬 Windows lock。
4. 根据用户 2026-10-25 的明确选择，移除 CPU 构建，使用 PyTorch CUDA 12.8；实测矩阵、NMS、卷积和单张 YOLO + SAM GPU 链路。实际运行记录了 1 次 DeepSeek 请求和用量；后续任何外部 API 调用先取得用户明确同意。
5. 启动并检查工作台 HTTP 服务；浏览器操作另记证据。本轮不做 CPU 性能基准，不由笔记本 GPU 耗时直接推断云实例性能。

**交付：**Linux 说明、资源报告、依赖方案、真实双路结果。**验收：**Linux 下确有两路独立结果，配置错误明确失败，既有误识别保留。

## S2：API 与双路线网页

**通俗解释：**Gradio 是操作窗口，API 是后台接单规则。

1. 将界面状态与推理业务分开，新服务层调用既有检测和大模型模块。
2. 设计 `GET /health`、`POST /api/v1/runs`、`GET /api/v1/runs/{run_id}`，明确参数、路线、状态和错误。
3. 保留 32 MiB 原图/格式校验、随机任务 ID、两路字节哈希校验；默认仅本地路线，云端路线显式确认。
4. 将既有 Gradio 挂载到同一服务，保留阈值、独立结果、错误与 ZIP 导出。
5. 验证正常、空结果、损坏图、超大文件、远端失败；健康检查不触发推理计费。

**交付：**API、契约、接口文档、页面接入与检查。**验收：**HTTP 发起并查询任务，页面经共用执行层运行，单路失败不伪造零。此阶段暂用进程内状态，重启会丢，S3 替换。S2 代码与本地 GPU HTTP 联调完成；真实 DeepSeek HTTP 请求和浏览器手工视觉验收待做。

## S3：数据库与历史增删改查

**通俗解释：**每次识别登记成能按编号查询的记录。

1. SQLAlchemy 定义任务、路线结果和产物索引，记录 ID、时间、参数、图像哈希、状态、耗时和错误。
2. SQLite + 迁移脚本；图片/掩膜放私有目录，表中记录位置。
3. 创建、分页列表、详情查询；更新备注、删除记录覆盖 CRUD，备注不改原始识别结果。
4. 页面增加历史入口，文件清理限受控目录，运行中任务禁止删除。
5. 检查事务、非法 ID、路径边界与重启持久化，失败也要入库。

**交付：**模型、迁移、历史 API/页面与清理规则。**验收：**真实识别后重启仍能查到结果；未加登录时仅限本机。

## S4：登录、JWT 与权限

**通俗解释：**先认人，再决定能查哪张记录。

1. 预建少量演示账号，密码安全哈希存储，不开放公共注册。
2. 登录签发短期 JWT，验证签名/过期/用户状态，签名密钥私下配置。
3. 任务绑定用户，上传、列表、详情、删除、图片与 ZIP 下载统一校验归属；退出清理客户端凭据。
4. Gradio 和 API 共用身份，接口也要验证，不能只藏按钮。
5. 检查错误密码、伪造/过期令牌、未登录和跨用户读写/下载。

**交付：**登录页面、认证、账号初始化、权限检查。**验收：**未登录不能识别，跨用户不可读；登录通过 HTTPS 或受控隧道。完整生产账号生命周期作为扩展。

## S5：消息队列与独立 worker

**通俗解释：**网页取号，后台做识别，拿编号查结果。

1. Redis broker + Celery worker；Web 创建持久任务再入队，返回任务号。
2. 明确 `queued → running → succeeded/partial_failed/failed`，两路分别保存状态，允许部分成功。
3. worker 初始并发 1；两路各读原图，网页轮询授权结果接口。
4. 规定投递失败、超时、中断、重复投递。DeepSeek 调用开始后若中断，标记结果未知/待确认，不自动再次计费调用。
5. 检查两个任务排队、网页断开后查询、worker 重启与错误可见性。

**交付：**生产/消费代码、worker 启动、恢复规则与证据。**验收：**独立进程执行，断浏览器不丢任务；Gradio 内存队列不能替代此项。

## S6：Linux 上 Docker 与 Compose

**通俗解释：**运行环境装箱，重要数据放箱外。

1. Dockerfile、`.dockerignore` 固定 Python/Linux 依赖和中文字体，区分 CPU/GPU。
2. Compose 组合应用、worker、Redis 与 Nginx；模型只读挂载，数据库/结果/必要队列状态持久化。
3. `.env.example` 描述参数；真实密钥、密码、上传图与权重不烘焙进镜像。
4. Linux 实际构建启动，查健康/日志，执行一张真实图片双路识别。
5. 重建确认数据不丢，检查 worker/Redis 故障；若用 GPU，另验宿主驱动与容器可见性。

**交付：**镜像配置、Compose、模板、启停/排错命令和日志。**验收：**按文档重新构建启动、重建保留历史；配置解析通过不能当实际容器成功。

## S7：Nginx 与服务器访问

**通俗解释：**给跑通的应用加入口，让另一台电脑能用。

1. 核对实例、公网连接、SSH，在云端部署已验证版本。
2. Nginx 代理页面/API，支持必要流式连接；为 32 MiB 文件预留 Multipart 开销，设置合理超时。
3. 安全组只开放必要入口，SSH 限来源，Redis/数据库/内部 Gradio 不裸露公网。
4. 选 HTTPS 域名或 SSH 隧道等受控演示方式，按实际地域规则处理备案/证书，不明文公网登录。
5. 在另一台电脑登录、上传、查历史、下载和检查失败，记录版本与脱敏日志。

**交付：**代理配置、云说明、访问方式、关闭计费资源提示和验证。**验收：**老师同学设备实际跑完真实任务，权限仍生效；SSH 凭据不公开。

## S8：验收、讲解与上交

**通俗解释：**实际演示证明完成，再讲清为什么这样做。

1. 完整检查登录、同图上传、排队、双路结果、历史、导出、错误和重启持久化。
2. 录启动和网页操作，显示运行状态，不用截图拼接冒充连续操作，不拍密钥。
3. 更新介绍、架构、参考、问题解决记录和待用户确认的个人感悟。
4. 核对源码版本、私有资源清单、复现边界与已知限制。
5. 提交推送 FDSF，标记实际验收版本；大视频另交可访问附件，仓库写位置。

**交付：**仓库、说明、视频、启动步骤、验收记录与提交号。**验收：**代码/录像版本一致，用户能解释修改核心代码；不能只交计划。

## 每一步如何向你说明

开始说“解决什么问题”；过程中说“改哪个模块、为什么”；完成说“改动、命令、结果、限制、提交号和下一步”。技术词配通俗解释，命令注明在哪台机器和目录运行。

每阶段填写[记录模板](第三阶段运行记录模板.md)，更新[开发记录](../第三阶段开发记录.md)，检查后提交推送，再停下来讲解，等待用户继续。用户明确继续某阶段后，在该阶段范围内逐步实施、每步汇报，注明设备和预计耗时；付费外部模型调用另征明确同意。外部条件缺失如实记录，不能写成成功。
