# S3 SQLite 任务历史

**S5 更新：**当前 schema v3，增加执行令牌、心跳和路线开始标记。默认 Celery 模式下 Web 重启不再直接终止 queued/running；只恢复心跳已过期的执行。独立 worker 已在本机验收，最新启动与恢复见 [S5 说明](第三阶段S5-队列与恢复说明.md)。下文的启动即标失败属于 S3/显式 inline 模式。

S3 把 API 上传任务和工作台任务写进同一个本机 SQLite 数据库。以前工作台结果只在当前页面会话里；现在页面关闭或服务重启后仍能按任务编号查历史。通俗理解：数据库是任务登记簿，图片和掩膜留在登记簿旁边的受控文件夹里。

## 数据保存

- 默认数据库：`runs/stage3.sqlite3`，SQLite WAL 模式，外键约束开启。该目录被 Git 忽略；S4 已升级到 schema v2。
- 上传原图及路线输出：`runs/stage3-api/<run_id>/`。数据库只存相对路径、图像 SHA256/尺寸/类型、参数、状态、时间、摘要和产物索引；API 返回数据不泄露服务器绝对路径和原始上传文件名。
- `runs` 保存任务和备注；`route_results` 保存 YOLO 与 DeepSeek 各自独立的结果；`artifacts` 索引可下载产物名称。外键级联删除关联结果与索引。
- S3 初始 `schema_version` 为 1；S4 将升级到版本 2，新增账号、登录会话和任务所有者字段。迁移保留旧任务但不猜测其所有者，登录用户看不到无主旧记录。未知的更高版本会拒绝启动；不要手工改生产数据库表。

SQLite 适合当前单机、少量演示。S4 已为新增任务增加用户归属；备份/恢复命令和独立 worker 仍待做。DeepSeek 路线仍须在界面或 API 明确确认。

## 启动和迁移

在 FDSF 根目录、Python 3.12 项目环境运行：

```console
python environment/migrate_stage3_db.py
python -m deskvision.api
```

首次启动会自动初始化数据库；第一条命令可用于手工预建或检查版本。API 仍监听 `127.0.0.1:8000`，工作台地址是 `http://127.0.0.1:8000/ui/`，接口文档是 `http://127.0.0.1:8000/docs`。停止服务使用 `Ctrl+C`。

服务启动时会把上次意外中断后仍处于 `queued` 或 `running` 的任务标记为 `failed`，错误代码为 `interrupted_by_restart`，不会自动重跑，以免重复产生模型调用或 DeepSeek 用量。已完成任务和文件保留。

## 历史操作

HTTP API：

| 操作 | 请求 | 说明 |
|---|---|---|
| 分页列表 | `GET /api/v1/runs?limit=20&offset=0&status=succeeded` | limit 为 1～100，status 可省略 |
| 单条详情 | `GET /api/v1/runs/{run_id}` | UUID；返回任务、两路结果、备注和产物 URL |
| 更新备注 | `PATCH /api/v1/runs/{run_id}/note` | JSON `{"note":"课堂演示"}`，最多 1000 字符 |
| 删除记录 | `DELETE /api/v1/runs/{run_id}` | 成功返回 204；运行中返回 409；同时删除受控任务目录 |
| 下载产物 | `GET /api/v1/runs/{run_id}/artifacts/{route}/{name}` | 只开放报告登记的名称，拒绝路径穿越和符号链接 |

工作台的“历史记录”页支持刷新、查看详情、保存备注和删除。列表展示最近 100 条，路线摘要只统计状态成功且数量为整数的结果；缺失或失败显示为“—”，不会伪装为零。删除运行中的任务会被拒绝。备注不改变识别结果。

## 检查

在项目环境运行：

```console
python environment/verify_stage3_s3.py
```

离线检查覆盖初始迁移与重复初始化、未知 schema 拒绝、任务与产物 CRUD、分页过滤、备注边界、非法 ID、路径边界、运行中删除保护、数据库连接重建后的持久化/恢复，以及 Gradio 工作台挂载。测试使用临时目录和模拟推理，不加载模型、不访问 DeepSeek，也不是浏览器人工验收。报告写到 `reports/stage3-S3-<system>-checks.json` 和 `.txt`；未脱敏执行日志在被忽略的 `runs/stage3/S3/`。

S3 页面人工视觉验收、数据库自动备份和独立 worker 仍待做。登录与任务权限见 [S4 说明](第三阶段S4-登录与权限说明.md)。真正给同学远程访问前，还要完成 S5～S7 的队列、容器和受控网络入口。
