# 第六阶段：DeepSeek 独立识别

2026-10-23～24（Asia/Shanghai）实现并完成两次真实 API 验证。用户选择 DeepSeek，并将 API Key 保存在本地后授权验证。使用当前官方支持图片输入的 `deepseek-flash`，调用地址 `https://api.deepseek.com`，复用已有 OpenAI SDK 2.16.0，无需安装新环境。

## 两条路线相互独立

| 路线 | 输入 | 本阶段输出 |
|---|---|---|
| YOLOv8 → SAM 2 | 原图与本地模型权重 | 像素框、检测分数、掩膜、轮廓、八类计数 |
| DeepSeek 图像理解 | 同一原图、八类定义与固定格式要求 | 逐件类别、中文相对位置、存疑标记、八类计数与说明 |

大模型入口不导入 YOLO、SAM 或训练模块，不读取检测结果、人工标签、训练权重或历史对话。训练模型入口也不调用大模型。大模型不参与训练、补标或纠正第一路结果；第一路结果不进入第二路提示。两路的数量只在生成结束后作比较，统一操作和展示放在第七阶段。

大模型暂不要求像素框或掩膜，不把自然语言位置伪装成精确定位；没有大模型的检测 mAP、校准置信度或分割准确率。`uncertain` 只是模型自报的存疑标记，全部为 false 也不代表答案正确。

## 本地配置与运行

密钥放在被 Git 忽略的 `.local/deepseek.env`，或设置当前进程环境变量 `DEEPSEEK_API_KEY`。环境变量优先，不输出密钥。不要把密钥填写到公开 JSON 或对话里。本机已经配置，无需重填。

其他机器可建立 `.local/deepseek.env`，内容为 `DEEPSEEK_API_KEY=你的本地密钥`。公开参数模板见 [vlm.example.json](../configs/vlm.example.json)，需要调整时复制为 `.local/vlm.json`。默认直接使用官方 `deepseek-flash`、60 秒超时、4096 输出 token 上限、JSON 模式、关闭思考模式、`detail=high`。本阶段仅验证官方端点和模型，不自动切换其他服务或模型。

在项目根目录执行：

```powershell
. .\environment\activate-ai-cuda.ps1
# 只检查参数与密钥是否可读取，不联网、不检验账号额度。
python -m deskvision.vlm --check-config
# 下面的调用会把所选原图发送到 DeepSeek，并产生 API 用量。
python -m deskvision.vlm --image data/desk8-train-v1/images/val/loco_val_000.png
```

换成自己的图片路径即可；不会自动读取另一路结果。支持 `--output` 更换输出根目录，`--config` 显式指定不含密钥的 JSON 配置。默认输出在 `runs/vlm/日期时间-随机编号/`，每次独立保存：

- `request-summary.json`：原图哈希、尺寸、MIME、模型、提示版本和请求哈希，不保存 API Key 或图片 Base64。
- `response.txt`：服务正常返回的最终回答文本；未解析成功时也不能据此判作成功，不保存思考过程。
- `result.json`：成功清单、数量、用量、耗时，或者明确的失败阶段与安全错误分类。

图片按照实际内容判断 MIME，保留原文件字节，不缩放、不裁剪、不叠加检测框。仅允许单帧 JPEG、PNG、WebP、GIF，单边不超过 8192 像素、文件不超过 32 MiB。Base64 是二进制数据的文本传输编码，不是 embedding。云端仍会按其规则预处理图片，因此两路收到相同原图不意味着内部缩放、计算量相同。

## 结构化结果与失败

固定提示保存在 [vlm-system-prompt.txt](../configs/vlm-system-prompt.txt)，版本 `desk8-independent-v1`，类别定义与标注规范一致。系统消息提供任务与规则，用户消息提供原图；不提供任何图片的计数答案。提示里的单杯 JSON 只演示格式，不能当作答案。

模型输出包含 `items`、`counts`、`notes`。每个物体一条记录，包括 `category_key`、中文相对位置 `location` 和布尔值 `uncertain`。八类全部计数必须为非负整数，且严格等于逐件清单中的条数。本地按项目编号输出 `summary`，方便后续 UI 对齐。

API 的 JSON 模式只保证语法，不能保证识别正确，也不能代替字段校验。拒绝未知类别、缺少字段、重复 JSON 字段、布尔计数、负数、非有限值、代码围栏和清单／汇总矛盾。不会静默修改数量、抽取“看起来像 JSON”的片段或自动让模型重答。

连接失败、超时、401 认证失败、403 权限、429 限流、其他服务状态码、空回答、拒绝、工具调用或输出截断均为失败，命令返回 1。失败报告不附带伪造的零计数，也不回退到 YOLO。输入或密钥配置失败会在联网前停止。本地输出目录已建立时保留失败 JSON；配置尚未通过、目录无法建立或无法写盘时只显示安全错误。

默认关闭 SDK 自动重试，单次启动最多发起一次模型请求，不自动增加调用次数。超时为网络操作超时，不保证服务端已经取消计算；失败也不能推断一定不计费。模型回答中的文字是待核对数据，不执行其中的指令。

先完成 SDK 模拟传输与输出校验，再向 DeepSeek 发出两次请求。没有使用独立测试组，也没有依据回答调整提示或模型参数。原始结果留在本机，入库摘要见 [第六阶段检查报告](../reports/stage6-vlm-checks.json)。

|---|---|---|---|---|---|
| `loco_val_000.png` | 螺丝 2、螺母 2、垫圈 2 | 三类各 2 | 三类各 2 | 4015.888 ms | 输入 1668、输出 189 token |
| `oi_38451ec391f20ab5.jpg` | 杯子 1、瓶子 1 | 杯子 1、瓶子 1 | 杯子 0、瓶子 2 | 2979.287 ms | 输入 1154、输出 81 token |

两张图的八类计数向量均与已有人工标签一致，但这只是接口验证，不是总体准确率或独立测试结论。五金图的自然语言位置没有验收，附加说明把垫圈描述为“弹簧垫圈”，该细分描述不能作为已确认事实。两个正确的计数向量不能证明每个物体定位正确。没有验证八类的完整覆盖、密集物体、真实桌面泛化或稳定性。

API 耗时包括网络与生成，只记录本次观察值；不能直接与 YOLO 的纯 GPU 推理时间比较。后续应使用相同范围的端到端耗时，区分冷启动与模型常驻。这里只记录实际 token 用量，不凭当前网页价格推算历史账单；费用以所选服务账单为准。

共 40 项单元测试通过，其中 11 项为大模型契约检查，包含真实 SDK 序列化、失败不重试、错误不泄露测试凭据、空输出与零物品区别。真实不存在图片也已确认在请求前失败。另用全新解释器确认大模型入口未加载 `ultralytics`、`sam2` 或 `torch`。

## 本阶段理解的概念

一次 API 调用相当于把“原图和答题规则”交给另一位识别者，接回一张结构化答卷。SDK 负责把 Python 参数序列化为 HTTPS 请求并处理响应，不等同于模型本身。提示要求统一八类口径，JSON 则让程序能核对答案形式；都不能消除幻觉或计数错误。

文本会被拆成 token，图片也会转换为模型可处理的视觉单元，并计入用量。embedding 是这些单元在模型内部的向量表示；attention 让模型结合不同单元的信息；位置信息帮助区分顺序与空间关系。视觉编码与文本生成共同构成多模态理解和输出，这里只调用接口，没有自行实现 Transformer。

编码器／解码器是理解模型的一种通用划分：编码侧把输入变为特征，解码侧生成输出。SAM 2 的图像编码一次、按提示解码掩膜是项目中可直接观察的例子。不能据此推断 DeepSeek 服务的全部内部架构，也不能把“有多模态输入”直接说成某一种固定编码器／解码器设计。
