# S4 登录与任务权限

S4 在 S3 任务历史上增加少量预建账号、密码哈希、短时 JWT 会话和所有权检查。账号由管理员在本机命令行创建；应用没有开放注册页面。

## 在本机首次设置

在 FDSF 根目录与项目 Python 环境运行：

```console
python environment/migrate_stage3_db.py
python environment/manage_users.py init-local
python environment/manage_users.py create-user teacher01
python -m deskvision.api
```

`init-local` 在忽略目录 `.local/auth.json` 生成随机 JWT 签名密钥，并开启只对本机开发使用的 HTTP Cookie。它不会把密钥打印到终端或写进 Git。`create-user` 会在终端要求输入并确认密码，密码不回显；库里只存 Argon2id 哈希。创建老师/同学账号时用不同账号名重复运行。建议演示密码至少 12 个字符，不要复用学校或常用网站密码。

也可以一次生成两个随机本机演示账号：

```console
python environment/manage_users.py create-demo-users
```

账号名为 `teacher01` 和 `student01`，随机密码只写入 Git 忽略的 `.local/demo-accounts.json`，不会打印到日志；演示前在本机打开该文件读取密码，提交或共享前应删除并重新创建。

打开 `http://127.0.0.1:8000/login` 登录。`python -m deskvision.ui` 和 `python -m deskvision.web` 也会启动同一套受保护的 API/工作台，不再启动免认证的旧入口。工作台显示账号名并提供退出登录。

停用账号及撤销它的所有现有会话：

```console
python environment/manage_users.py disable-user teacher01
```

忘记密码时没有网页找回流程；管理员须线下确认身份后用命令重置。多因素认证、找回流程和自助注册不在本阶段范围内。

```console
python environment/manage_users.py set-password teacher01
```

重设密码会撤销该账号的所有旧会话，并重新启用账号。

## 认证如何工作

成功登录后，服务签发固定 HS256 算法、30 分钟有效的 JWT，并放进 `HttpOnly`、`SameSite=Strict` Cookie。浏览器脚本不能读取 Cookie；本机允许 HTTP，生产默认要求 HTTPS Cookie。API 客户端也可通过 `Authorization: Bearer <token>` 请求。`/health` 和登录页公开，其余任务、文件、Gradio 页面、上传和回调需要有效登录。

服务每次请求检查签名、签发方、受众、过期时间、账号是否启用，以及数据库会话是否已撤销。退出会在数据库撤销当前会话并删除 Cookie；停用账号也会撤销所有会话。JWT 不包含可由客户端决定的任务权限。

任务表增加 `owner_id`。新 HTTP 和工作台任务在创建时写入当前账号；列表、详情、备注、删除、产物和 ZIP 导出均按当前账号过滤。其他账号猜到任务编号也只会得到 404。ZIP 经用户专属 API 生成，不再从共享 Gradio 文件目录公开链接；包中不含内部 `result.json`。

## S3 数据库升级

数据库 schema 从版本 1 迁移到 2，新增用户/登录会话表和 nullable `runs.owner_id`。升级保留原来的任务和结果；旧任务没有可靠的账号归属，因此 owner 保持空值，所有普通账号都看不到这些旧记录。不要把旧任务自动分配给首个新账号。

迁移在事务中执行，可重复运行：

```console
python environment/migrate_stage3_db.py
```

已有 SQLite 文件与 `.local/auth.json` 都属于私有运行数据，不会随源码提交。新服务器应先准备私有资源并初始化密钥/账号，不能把本机 JWT 密钥提交或拷贝进仓库。

## 验收检查

在 Windows ai-cuda 或兼容 Python 环境，从项目根目录执行：

```console
python environment/verify_stage3_s4.py
```

离线检查覆盖 S3→S4 数据库升级、未登录拒绝、正确/错误凭据、Argon2 哈希、过期/伪造/撤销 token、账号禁用、不同账号读取/备注/删除/文件/ZIP 隔离、Gradio 上传/预览/队列/SSE 归属、固定模型路径、跨站修改拒绝和迁移重复运行。识别以替身执行，不加载 YOLO/SAM、不请求 DeepSeek；当前记录为 105 项运行、104 项通过、1 项 Windows 符号链接权限跳过。

本机启动服务后可运行真实浏览器检查（使用 `.local/demo-accounts.json` 中的本机账号，不执行推理）：

```console
node environment/verify_stage3_s4_browser.cjs
```

## 部署边界

本机数据库里的旧历史保持无归属，不会直接共享给新账号。本机开发配置不适合上传服务器；服务器需用 HTTPS，设置 `local_http=false` 并独立生成新 JWT 密钥，创建演示账号。身份代码和本机测试在 S4；服务器密钥、域名证书、安全组和远程登录验收属于 S7。

当前版本尚无登录频率限制、并发会话管理页面、自动账号过期、密码重置和密钥轮换机制。登录入口只用于之后受控的演示部署；公网开放前仍须完成 S5 队列、S6 容器和 S7 HTTPS/网络控制，并进行安全复核。
