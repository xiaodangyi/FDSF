# 验收与复现指南

## 本机五分钟验收

在 `E:\新建文件夹 (9)` 打开 PowerShell：

```powershell
. .\environment\activate-ai-cuda.ps1
python environment/verify_project.py
python -m deskvision.ui
```

打开 http://127.0.0.1:7860/ 。若该端口已有本项目界面，直接使用；只有需要另启实例时才指定 `--port 7861`。服务仅监听本机，不创建分享链接。

1. 上传 `data/desk8-train-v1/images/val/oi_38451ec391f20ab5.jpg`。人工真值杯子1、瓶子1；默认选八类最佳权重、0.25 阈值并启用 SAM。
2. 运行本地路线，观察检测框、两只瓶子的错类结果和 SAM 掩膜。SAM 没有改掉错误，不能把“有掩膜”当识别正确。
3. 运行 DeepSeek。此操作将原图发送 DeepSeek 官方服务，产生 API 用量；已有演示回答是杯1瓶1，未来回答可能变化。未配置密钥或网络失败时看明确的错误，不当作零个物体。
4. 查看八类差异和各自耗时，下载 ZIP，检查 `yolo/`、`deepseek/` 与数量对比。页面详细 JSON 可追查原图 SHA256；两路必须同图。
5. 改阈值应清除本地结果、对比与旧下载，保留当前 DeepSeek 结果；换图应清除两路结果。若想保留当前演示，先下载再操作。
6. 展示 [完整固定实验](第八阶段实验报告.md) 的九张结果和两张错误图，说明小样本与真实桌面缺口。上述 UI 图片属于验证组，不加入测试统计。

也可以上传自己的非敏感桌面照片，先人工记录八类真值，再看两路输出；该观察另记为现场演示，不能冒充原协议中的固定测试结果。

## 离线核查固定实验

本机已经完成首次测试，不需要再次付费调用：

```powershell
. .\environment\activate-ai-cuda.ps1
python -m deskvision.acceptance summarize
python -m unittest discover -s tests -v
git diff --check
```

`summarize` 只校验并读取已有结果，不加载模型推理、不联网；需要冻结资产和相同依赖版本，输出会更新汇总的生成时间。57 项测试包括协议与缓存校验、失败不当零计数、独立输入、SDK 序列化、图像/参数变动的失效保护和导出范围。单元测试不会向真实服务发送请求，也不训练。

`python -m deskvision.acceptance run` 会保留每张每路已有记录，包括失败和中断，不自动重试；只有缺少记录时才进行相应推理或付费请求。因此不要为观看结果而删除记录。`freeze` 已完成并拒绝覆盖；当前九张已看过答案，不应再次当新盲测。要研究新模型或新提示，应保留此次协议并另建新版本与独立测试集。

若源码、权重、图片、标签或依赖版本改变，哈希/版本检查应失败。不要为了绕过校验重写旧协议。云端服务可能更新，固定请求不能保证未来回答逐字一致。

冻结源码、提示、类别配置和协议的 Git 属性设为保留原始字节，避免 Windows 自动换行改变 SHA256；复制文件时也应保留字节，不用编辑器重新保存旧协议。

|---|---|

| `reports/stage8-results.json` | 入库脱敏逐图计数、耗时、token、状态和报告摘要指纹 |
| `runs/acceptance/stage8-v1/` | 18 份原始运行记录，以及两路图片、JSON、掩膜和响应文本；部分报告含本机绝对路径 |
| `runs/train/desk8-full-20261023-204546/weights/best.pt` | 此次最佳八类检测权重；未提交到 Git |
| `models/sam2.1_hiera_tiny.pt` | SAM 权重；未提交到 Git |
| `data/desk8-train-v1/` | 本机完整64张导出及清单；未提交到 Git |
| `runs/stage8-demo/验收演示.mp4` | 36 秒 H.264 截图序列视频，无配音；不是连续录屏 |
| `reports/stage8-demo.json` | 视频格式、完整解码检查与 SHA256 |
| `reports/assets/` | 入库错误图、真实界面截图与来源许可 |
| `runs/delivery/验收证据与推理资源.zip` | 本地交付包：源码文档、固定实验原始记录、九张测试及演示验证图、两份权重、视频；不含密钥、解释器、完整训练集 |

交付包按明确文件清单生成，内含文件 SHA256 清单，用于核对材料与已有实验。权重、公开测试图片遵守各自来源许可，尤其 LOCO 的非商用和相同方式共享要求。原始报告中的绝对目录用于追溯原机器，迁移后不能依赖该路径直接定位产物；包内相对目录保留了实际产物。交付包可核对既有记录并运行推理，**不包含完整训练重放所需数据，也不保证离线安装环境或离线调用云端服务**。

本机整理材料后可运行 `python -m environment.package_acceptance` 重新打包；脚本不调用模型或 API，会检查协议资产、文档链接、同图导出，并在内存中读取本地密钥做精确泄漏扫描。它仅适用于保留本阶段原始产物的工作区。包内 `delivery-manifest.json` 列出每个文件的大小与 SHA256；包外 `runs/delivery/package-verification.json` 保存整包 SHA256、CRC、逐文件哈希和密钥扫描结果，避免文件自引用。工程核查记录见 [检查摘要](../reports/stage8-checks.json)。

Git 仓库不含权重、数据、运行产物或本地密钥，不能仅克隆后直接运行。另一台机器需：

1. 按 [环境说明](../environment/README.md) 准备 Python 3.12、兼容 NVIDIA 驱动及固定版本依赖，使用协议中的版本核对；本机无需重装。
2. 将本地交付包解压到新的项目目录，保留相对路径。不要覆盖仍在开发中的工作区。
3. 参考 `configs/local.example.json` 建立忽略的 `.local/config.json`，填写新的 `ai_cuda_root`；`sam2_weights` 指向 `models/sam2.1_hiera_tiny.pt`。界面默认使用项目内的最佳八类权重。COCO 基线及环境 smoke 检查另需已有 COCO 权重与素材，包内没有这些额外资源，相关项目检查不能宣称在新机器全部通过。
4. `summarize` 不需密钥，可验证已有记录；本地推理只需准备权重/依赖。新调用 DeepSeek 时，在 `.local/deepseek.env` 本地填写密钥，运行 `python -m deskvision.vlm --check-config`，不要把密钥写进文档、ZIP 或仓库。
5. `freeze` 要完整原始导出及复核依赖，而且当前协议已存在；不在验收包上再次冻结。需要训练重放时，另外复制完整64张数据、候选/复核记录和训练配置，再按阶段四说明进行，不能以本包声称完整重训可复现。
