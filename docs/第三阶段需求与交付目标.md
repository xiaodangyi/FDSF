## 完整项目的四项交付目标

| PDF 原文节点 | 本项目落实方式 | 验收证据 |
|---|---|---|
| 复用第二阶段的对比项目，将已有两种方案改造成可操作的 Web 应用 | 保留既有模型与 Gradio，新增服务层 | 浏览器上传、双路运行，源码能定位各模块 |
| 输入同一图片，并排展示 YOLO/SAM 与多模态大模型处理结果 | 校验原图哈希，展示检测/分割、清单、数量、耗时与错误 | 同图双路结果、单路失败处理、导出 |
| 用 Linux + Docker 部署服务器，页面、后端接口与模型正常联通 | 在 Linux 实际构建、启动并执行识别 | 系统版本、容器状态、健康接口与真实推理记录 |
| 展示网页运行与项目启动过程，记录环境、依赖和启动步骤 | 编写可执行的复现说明并真实录屏 | 启动记录、脱敏日志和网页操作视频 |

项目继续识别杯子、瓶子、书、橡皮、螺丝刀、螺丝、螺母、垫圈。YOLO 检测框提示 SAM 2；DeepSeek 独立读取原图，完成后才比较，不提前互相提供答案。

用户补充的约束：老师/同学临时演示；第三阶段代码和记录统一提交 [FDSF](https://github.com/xiaodangyi/FDSF)。这些不是 PDF 原文。

## 学习内容逐项映射

左侧是学习点，PDF 没有给每项单列评分或实现深度。本路线逐项安排最小实现，避免漏掉认证和队列；斜杠分隔的替代框架无需全部同时使用。

| 分支 | PDF 内容 | 本项目实现选择 | 阶段 |
|---|---|---|---|
| FastAPI / Flask | 接口设计、文件上传、参数处理与模型调用 | FastAPI 健康、上传、任务状态与结果接口 | S2 |
| SQLAlchemy | 数据库记录增删改查 | SQLite + SQLAlchemy，任务与历史管理 | S3 |
| Gradio / Streamlit | 输入页面，并排展示两种结果 | 保留 Gradio | S2、S3 |
| Linux 基础 | 文件、目录、权限、进程与日志 | 实际查看目录权限、启停进程、查日志 | S1、S6、S7 |
| Linux 远程操作 | SSH、依赖、环境变量、排错 | SSH 连接、依赖与故障记录 | S1、S7 |
| Docker 镜像与容器 | Dockerfile、构建、启动 | 固定 Python 3.12、Linux 依赖，先验证 CPU | S6 |
| Docker 服务组合 | Compose、环境配置、数据挂载 | 应用、worker、Redis、Nginx 与持久卷 | S6 |
| nginx | 反向代理、静态资源、网页服务 | 同一入口代理 API/UI，保护私有目录 | S7 |
| 身份认证 | 登录校验、JWT、接口身份识别 | 预建演示账号、密码哈希、JWT、任务归属 | S4 |
| 消息队列 | 生产消费、异步处理、结果返回 | Redis + Celery 独立 worker，持久状态 | S5 |

SQLite、Redis、Celery、Python 版本和具体 URL 是本项目选择，不冒称 PDF 指定品牌或数值。

4. **参考与创新：**教程和参考项目仅作参考，不推荐直接提交参考项目，鼓励拓展和创新。标注来源，保留自主业务、两路隔离、错误处理、历史查询和部署实现。
5. **AI 辅助开发：**鼓励使用 AI，理解代码并能够修改、排查问题。每阶段提供代码入口、通俗解释与可复现检查，验收前练习修改一个参数并解释影响。

## 已有与缺口

已有：YOLO、SAM 2、DeepSeek 独立调用、Gradio、JSON/图片/ZIP、基础进程内排队和离线检查源码。

待补：FastAPI 契约、数据库与 CRUD、账号/JWT、独立消息队列、Linux 实测、Docker/Compose、Nginx、受控远程访问和第三阶段录屏。监听 `127.0.0.1` 不代表远程可访问，Gradio 内存队列不等于消息队列，保存 JSON 不等于数据库。

旧九图实验和训练指标只是第二阶段的历史证据，不能证明第三阶段部署成功，也不能外推真实桌面泛化。

## 采购与环境边界

PDF 没有要求必须购买 GPU、域名、云数据库、OSS 或负载均衡。先用单机，CPU 实测后决定升级，不以推荐配置冒充性能验收。

Ubuntu 26.04.1 LTS 目前仅由用户提供，S1 通过 `/etc/os-release` 和 `lsb_release -a` 核验。容器内固定 Python；旧 Windows cu128 快照不能直接当 Linux 安装方案。域名、备案和证书按实际地域与服务方式办理；公网登录采用 HTTPS 或受控隧道。
